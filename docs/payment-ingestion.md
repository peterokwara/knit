# Payment ingestion

`PaymentFileRetrievalService.retrieveFiles(...)` reads the selected local files and returns their names, formats, and contents. It does not parse payment data. `PaymentIngestionService.importFiles(...)` adapts those contents into normalized events, then saves events and source observations in one transaction. Retrieval can change with the file source while provider adapters remain focused on data shape. Replaying the same files is safe. Stable provider references identify events; a changed financial payload under the same reference is retained as a conflict instead of overwriting prior evidence. Non-financial callback changes, such as M-Pesa's account-balance snapshot, create additional observations without creating another payment.

`PaymentFamilyMatchingService.matchPayments(...)` matches a payment's exact admission or family reference to one family. It trims surrounding whitespace and ignores letter case but never repairs a mistyped identifier. Missing, unknown, or ambiguous references, source-validation issues, and conflicting events are held for review. A known family reference in a non-billing currency remains attached to the family but is held until a valid currency conversion is available. These decisions are derived from the persisted events and the school's family references; this step does not yet persist a human resolution or allocate money to invoices.

M-Pesa amounts are stored in KES minor units. M-Pesa transaction times are converted from the school's local time zone. A reversal links to its original transaction even when it arrives first; the event read model keeps reversals out of payment totals. If linked reversals exceed the original payment, the records are held for review. Failed STK requests have no payment amount.

Bank amounts are parsed without floating point. The importer recognizes common header aliases, reordered columns, and either separate debit/credit columns or a single amount with an explicit direction. It rejects unknown layouts before writing the batch. Overlapping statement rows with the same account and bank reference become one event with evidence from both exports. Fees, M-Pesa settlement deposits, failed requests, conflicted records, and unclassified credits remain visible with zero net amount. Credits without a recognizable admission or family reference stay unclassified for review. Currency and parent-entered references remain attached to each transfer; the importer does not guess a corrected reference or convert foreign currency.

This stage records provider events and derives exact family matches; it does not allocate money to invoices or calculate balances. Run `pnpm payments:load` from `app/` to import the supplied fixtures into the local SQLite database and see the match/hold counts. The command is safe to rerun.
